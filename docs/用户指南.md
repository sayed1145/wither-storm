# 凋零风暴 v1.7.1：孔口连续发射与可移动 HUD

## 本次针对两个问题的修复

### 激光：修复实际绘制遮挡，不再只验证计算起点

v1.7.0 的孔位计算虽已绑定头部，但光束先画、整个身体后画的分层方式，把本来位于脸前的光束也盖掉了。于是视觉上会从下巴或身体边缘开始，而不是紫色孔。

现在身体与光束进入**同一个深度缓冲**：先写身体深度并绘制身体，再以该深度测试透明光束；透明光束不写深度，不会把身体挖空。孔口到外部的可见光束连续，真正位于前方的方块仍正常遮挡，不以“全部画在最上层”掩盖问题。保留紫色光束，收紧发射轴对准误差至 2°。

严格检查包括：
- 从导入头部的实际紫色方块前表面读取参照点，而不是重复比较两个起点计算函数；检查1,080组不同朝向/俯仰/偏转/成长状态。
- 用安装 JAR 在 GL2 与 GL3 绘制同一头模型的无光束、旧分层、共享深度三组画面。仅诊断光束临时改成绿色，方便从背景差分测量；生产颜色不变。
- 放大画面中，旧分层三个源点的可见间隙约275.48、200.80、152.58像素；修复后约0.19、0.64、1.04像素。两个后端一致。数值针对该放大诊断场景，不代表任意相机下的固定距离。

### HUD：默认避让，可分别拖动并保存

**设置 → 凋零风暴 →「布局编辑」开启 → 返回游戏 → 拖动友方或敌方面板 → 回设置关闭布局编辑。** 两个面板分别记录位置；正常模式不拦截输入。要恢复自动布局，点击同一设置页面的「重置敌我面板位置」。

- 默认布局检查当前可见的原生 HUD 控件边界，自动留出间距；两个汇总面板也相互避让。
- 自定义位置按窗口比例保存。换窗口尺寸后约束在屏幕内，落点有冲突时就近移到空处。
- 小窗口会先缩窄面板；空间不足时显示“收起”标题条。极端情况下完全没有空位则暂时隐藏该面板，而不是覆盖原生控件。放大窗口、关闭一个面板或缩小游戏 UI 后可恢复展开。
- 默认避让在实际1120×700、800×600、640×480、1280×720窗口中测试；此外1920×1080进行了矩形布局算法检查。实际GUI的拖动输入、设置文件保存/重读、越界限制均通过。
- 这是本模组两个汇总面板的布局编辑，不是任意第三方模组或游戏全部控件的编辑器。第三方自定义 HUD 组合、竖屏和手机真机未测试。

总计 **215项无界面检查通过**；专项光束/布局均通过 GL2、GL3 实际客户端检查。安装前备份存档并禁用旧版本。本版还重新运行了移动吸收、原生接管、触手、遮挡与分裂等回归场景；不承诺所有未测平台零缺陷。

完整包内的 `preview` 保存原始测试报告及关键 PNG。对照图中的绿色仅为诊断标色，实机演示使用正常紫色。

## 安装

1. **先备份存档**，禁用或移除旧版同名模组，不要同时启用多个版本。
2. Mindustry「模组 → 导入模组」选择 `Wither-Storm-v1.7.1.jar`，重启。
3. 实测引擎为 **官方 Mindustry v160.5**。建议先在新沙盒地图检查，再打开正式存档。
4. 原祭坛、破核炮、统御图腾及其配方保留。源码 ZIP 不是直接导入游戏的文件。

## 本轮修改

### 发射孔、身体和头部

- 光束起点读取**实际头部子骨骼的发射点**：成熟头使用下载模型的紫色孔前表面；普通头使用眼部发射点。子骨骼缩放、头部转动、俯仰、轻微摆动与全身成长一起计算，不再用头中心附近的估算位置。
- 身体朝向与位移分离。自主模式仍优先靠近最近的敌方单位；没有单位时才追建筑。原生移动指令和附身位移不被转身过程打断。
- 身体以每 tick 至多 1.8° 转向；头部左右偏转限制为 ±40°，发射轴误差收紧至 2°。身体相对目标超过 55°、或发射轴尚未对齐时，**激光及其牵引都不生效**。不是只隐藏图形、仍在背后拉人。
- 三个头没有人为的轮流开火计时；各自有可用目标、完成对准即可同时激活。成长到可用阶段，不代表可以绕过新的朝向条件。
- 原有的**近场无光束生物吸收、独立建筑吸收**继续并行，不受激光朝向开关取代。敌人在近场仍可能被这套独立机制吸收；这不代表存在背向激光。
- 移除了生成颈部的骨骼与几何。成熟头的安装点收回躯体前缘，头后部嵌入身体，保留已接受的 Witherbean 46 方块头和真实深度遮挡。

### 每根触手独立攻击

- 每根已长出的触手有自己的 **18 tick 蓄力 → 12 tick 挥击 → 24 tick 回收**；再次发动至少间隔 72 tick。
- 只有挥击到达第 30 tick 的击中时刻，才沿同一条动画曲线检查敌人并结算伤害。闲置接触、蓄力、回收不再直接扣血。
- 近距离地面和空中敌人都可以被击中；友军不受伤。目标闪避离开击中区域时可以打空，不是锁定后必中的接触伤害。
- 身体转向、头部瞄准和未完成的触手攻击状态写入存档与同步数据（新版本号 6）。旧 v1.6 的“命中后反应时间”不会被错误解释为一次新攻击。

### HP 与敌我汇总

- 每只风暴显示当前 HP / 最大 HP 和血条，数字大小会随镜头缩放补偿。
- **友方汇总**与**敌方汇总**分开显示：存活数量、总物质量、当前/最大总 HP、吞噬单位数、吞噬建筑数、吸收中的建筑数及核心完整度。
- 统计当前世界中已同步的存活风暴实体，包含分裂体；不是只选第一只。敌方面板合计其他非中立阵营。吞噬数是这些存活实体的计数总和，不是全局永久战绩。
- 核心完整度与外壳 HP 是两回事；厚壳阶段仍需要破核炮等原有专门机制。

**游戏设置 → 凋零风暴** 可以调整：

| 选项 | 默认 |
|---|---|
| 显示风暴汇总面板 | 开 |
| 显示友方 / 敌方汇总 | 分别开启 |
| 核心详细统计 | 开 |
| 每只风暴血条 / 血量数字 | 分别开启 |
| 面板宽度 | 360，范围 280–520 |
| 面板不透明度 | 90%，范围 30–100% |

原有详细几何、紫色环境效果、音乐和音量设置保留。面板不截获鼠标或触摸输入。

## 操作与保留机制

- 桌面默认 **Ctrl + 点击盟友风暴的地面中心/影子**附身，WASD 移动，鼠标瞄准/攻击，**V** 脱身；以游戏自定义键位为准。不要点高处模型代替地面选取点。
- 前后期都可接管；不能接管敌人、抢走其他玩家控制的单位，服务器原生接管权限仍有效。
- **统御图腾在逻辑分类**，2×2，70 硅、45 钍。单击切换，无配置菜单：开=停止自主追敌但服从原生指挥，关=自主托管。不会夺取已附身个体的控制权。
- 指挥状态可用原生单位指令移动或攻击。转向与移动独立，移动途中仍处理战斗和吸收。
- 范围外全速追近，进入对应范围后半速继续靠近；不恢复旧版的范围边缘停住行为。
- 初始完整身体、命令方块九点图案和三个普通凋零头保留；后期不发射骷髅。
- 建筑同时吸收从 5 个开始，随强度增长，最高 32 个；飞行过程 95 tick 后才记账。
- 建筑基础半径约 1040.44，近场生物约 520.22，光束约 3182.16 世界单位；仍按累计吸收缓慢增大，近场生物增长较慢。
- 被吸引地面/腿式单位临时抬升越墙；脱离牵引后恢复安全地面状态。抵达头部立即清除并入账，不依赖普通伤害耗尽护盾。
- 吸收回血、成长、分裂、重组、受保护命令核心和祭坛机制保留。
- 用户上传的黑/紫/白图集继续用于身体与环绕方块；第二排最后两块排除，九点核心材质独立。没有连续圆环，环绕方块最高 500 个，低细节模式最高 200 个。

## 源码与重建

完整包包含安装 JAR、全部源码、贴图、模型与许可证、测试工具、历史存档和验证结果。解压后 JAR 在 `release/Wither-Storm-v1.7.1.jar`；构建脚本自动从该 JAR 恢复继承音乐，避免重复保存相同资源。

使用 JDK17，依赖为官方 Mindustry v160.5 游戏/服务器、r8、Android android.jar。下载脚本 `tools/fetch_dependency.sh`，依赖默认放在 `$HOME/.cache/wd-vendor`。运行 `bash build.sh` 生成通用安装 JAR，`bash build.sh desktop` 仅生成桌面版。

运行 `bash tools/run_checks.sh headless`。新增桌面模式 `pixel / pixel2` 对照新旧光束遮挡；`layout / layout2` 检查真实窗口尺寸、输入事件拖动与设置文件重读。原有 aim、aim2、client、gl2、control2、animation、animation2、orbit2、fracture 模式继续可用。每次只运行一个图形客户端。图形测试需要 xvfb/Mesa。

先运行两个 pixel 模式，再运行 `python tools/verify_beam_pixels.py`；两个 animation 模式完成后运行 `python tools/verify_occlusion.py`。`tools/validate_release.py` 仅校验随包证据及 JAR，不替代实际游戏测试。
